# PRD: корпоративная wiki (MVP)

**Версия:** 1.0  
**Статус:** спецификация для реализации  
**Связанные документы:** [MVP-SCOPE.md](./MVP-SCOPE.md), [ROLES.md](./ROLES.md), [CONTENT-MODEL.md](./CONTENT-MODEL.md), [DEPLOYMENT.md](./DEPLOYMENT.md)

## 1. Продуктовое резюме

Self-hosted wiki с закрытым доступом по умолчанию, ролями Admin / Editor / Viewer, блочным редактором (Notion-like), поиском, версионностью, комментариями и публикацией отдельных страниц наружу по неугадываемой ссылке.

## 2. Персоны

| Персона | Цели |
|---------|------|
| **Администратор** | Развернуть систему, управлять пользователями и политиками, восстанавливать из бэкапа |
| **Редактор** | Вести базу знаний: структура, контент, публичные страницы при необходимости |
| **Читатель** | Находить и читать материалы, комментировать, получать уведомления |
| **Аноним** | Только просмотр страниц с включённой публичной ссылкой |

## 3. Сущности (ER на уровне продукта)

- `User`, `Session` / refresh-токены
- `Space`, `SpaceMember`
- `Page`, `PageVersion`
- `PublicShare`
- `Comment`, `Notification`, `Subscription` (страница / space)
- `AuditLog`

Детали полей — [CONTENT-MODEL.md](./CONTENT-MODEL.md).

## 4. Экраны и пользовательские потоки

### 4.1 Аутентификация

| Экран | Описание |
|-------|----------|
| **Login** | Email + пароль; ссылка «Забыли пароль» (если SMTP настроен) |
| **Invite accept** | Токен приглашения → установка пароля |
| **Password reset** | По email |

### 4.2 Основное приложение (авторизованные)

| Экран | Описание |
|-------|----------|
| **Home / Dashboard** | Список space, недавние страницы, подписки |
| **Space home** | Дерево страниц (сайдбар), быстрые действия |
| **Page view** | Чтение; кнопка «Редактировать» (Editor+); комментарии внизу |
| **Page edit** | Блочный редактор, автосохранение, статус видимости |
| **History** | Список версий → просмотр → сравнение → откат |
| **Search** | Глобальный поиск с фильтрами |
| **Notifications** | Список уведомлений (упоминания, комментарии) |
| **User settings** | Профиль, смена пароля, язык (опционально) |

### 4.3 Публичная страница

| Экран | Описание |
|-------|----------|
| **Public page** | URL `/pub/{token}`; без хедера приложения; опционально минимальный брендинг инстанса; комментарии — только если включены в настройках публикации |

### 4.4 Администрирование

| Экран | Описание |
|-------|----------|
| **Admin: Users** | Список, создание, блокировка, смена глобальной роли, invite |
| **Admin: Spaces** | Создание space, участники |
| **Admin: Settings** | Название инстанса, `PUBLIC_SIGNUP`, SMTP, политика комментариев по умолчанию |
| **Admin: Audit** | Просмотр последних событий с фильтром |

### 4.5 Ключевые потоки

1. **Создание знания:** Editor открывает space → создаёт страницу → пишет блоки → сохраняется автоматически → visibility `internal`.
2. **Публикация наружу:** Editor меняет visibility на `public` → модальное подтверждение → генерируется `token` → ссылка копируется.
3. **Откат:** Любой с правом открывает History → выбирает версию → «Восстановить» → новая версия с содержимым из прошлого.

## 5. Редактор: типы блоков (MVP)

- Заголовки H1–H3
- Параграф (inline: жирный, курсив, ссылка, код)
- Маркированный / нумерованный список
- Чек-лист
- Цитата
- Код (блок с подсветкой — желательно; иначе preformatted)
- Таблица (минимум: строки/столбцы фиксированной сетки)
- Изображение (upload в storage)
- Разделитель
- Внутренняя ссылка на страницу (picker)
- Упоминание `@user`

Slash-меню: ввод `/` открывает список блоков.

## 6. API (REST, черновой контракт)

Префикс: `/api/v1`. Авторизация: сессионная cookie или `Authorization: Bearer` (выбрать один способ в реализации).

### Auth

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/auth/login` | `{ email, password }` → сессия |
| POST | `/auth/logout` | |
| POST | `/auth/invite/accept` | `{ token, password }` |
| POST | `/auth/password/request-reset` | `{ email }` |
| POST | `/auth/password/reset` | `{ token, password }` |

### Users (Admin)

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/users` | Список с пагинацией |
| POST | `/users` | Создать пользователя `{ email, role, send_invite }` |
| PATCH | `/users/:id` | Роль, блокировка |
| POST | `/users/:id/invite` | Переотправить invite |

### Spaces

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/spaces` | Список доступных пользователю |
| POST | `/spaces` | Admin: создать `{ name, slug }` |
| GET | `/spaces/:id` | Детали + участники |
| PATCH | `/spaces/:id` | Admin / owner |
| POST | `/spaces/:id/members` | `{ user_id, role }` |
| DELETE | `/spaces/:id/members/:userId` | |

### Pages

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/spaces/:spaceId/pages/tree` | Дерево для сайдбара |
| POST | `/spaces/:spaceId/pages` | Создать `{ parent_id?, title, slug? }` |
| GET | `/pages/:id` | Метаданные + контент (если есть доступ) |
| PATCH | `/pages/:id` | `{ title?, content?, visibility?, parent_id?, position? }` — оптимистичная блокировка через `content_version` |
| DELETE | `/pages/:id` | Мягкое удаление |

### Versions

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/pages/:id/versions` | Список |
| GET | `/pages/:id/versions/:version` | Снимок |
| GET | `/pages/:id/versions/compare?from=&to=` | Diff |
| POST | `/pages/:id/versions/:version/restore` | Откат → новая версия |

### Public share

| Метод | Путь | Описание |
|-------|------|----------|
| POST | `/pages/:id/public-share` | Включить `{ noindex, comments_enabled, ... }` → `{ url, token }` |
| PATCH | `/pages/:id/public-share` | Настройки / выключить |
| GET | `/pub/:token` | **Публичный** endpoint без auth; отдаёт HTML или JSON для фронта |

### Comments

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/pages/:id/comments` | Древовидный список |
| POST | `/pages/:id/comments` | `{ body, parent_id? }` |
| DELETE | `/comments/:id` | Автор (окно времени) или Admin |

### Search

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/search?q=&space_id=&visibility=&mine=` | Поисковая выдача с snippet |

### Notifications

| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/notifications` | |
| POST | `/notifications/:id/read` | |

## 7. Нефункциональные требования

- **Безопасность:** хеш паролей (argon2/bcrypt), rate limit на login, CSRF для cookie-сессий
- **Производительность:** время ответа типичного GET страницы < 300 ms на сервере без нагрузки
- **Доступность:** семантическая разметка публичных страниц; клавиатурная навигация в редакторе — желательно
