# Модель контента: страницы, вложенность, публикация, версии

## Сущности верхнего уровня

### Instance (инстанс)

Логическая граница одной установки wiki: настройки, пользователи, все space.

### Space (пространство)

Контейнер для дерева страниц и политики доступа на уровне раздела.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | Первичный ключ |
| `slug` | string | Уникальный в инстансе; используется в URL `/s/{slug}/...` |
| `name` | string | Отображаемое имя |
| `description` | text | Опционально |
| `created_at` | timestamp | |
| `updated_at` | timestamp | |

**Участники space (MVP):** связь `space_members(user_id, space_id, role_space)` где `role_space` — `owner | contributor | reader` **или** упрощённо: все авторизованные с ролью системы Viewer+ видят space, если добавлены в список; Admin видит всё.

Рекомендация MVP: **список участников space** явно задаётся Admin; Editor добавляется в space как contributor; Viewer — как reader.

### Page (страница)

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | |
| `space_id` | UUID | Обязательно |
| `parent_id` | UUID, nullable | Корень space — `null` |
| `position` | int | Порядок среди соседей (сортировка в UI) |
| `title` | string | Заголовок страницы |
| `slug` | string | Уникален в пределах **родителя** (или в пределах space — выбрать одно правило и придерживаться) |
| `visibility` | enum | `private` \| `internal` \| `public` |
| `inherit_visibility` | bool | Если true, эффективная видимость наследуется от ближайшего предка с явной видимостью |
| `content` | JSON | Документ редактора: массив блоков (см. ниже) |
| `content_version` | int | Монотонный счётчик для оптимистичной блокировки |
| `created_by` | user_id | |
| `updated_by` | user_id | |
| `created_at` | timestamp | |
| `updated_at` | timestamp | |
| `deleted_at` | timestamp, nullable | Мягкое удаление |

**URL:** `/s/{space_slug}/{path...}` где `path` — цепочка slug от корня до страницы, **или** короткий канонический URL `/p/{page_id}` с редиректом на человекочитаемый — на этапе реализации выбрать один стиль; для MVP достаточно `/s/{space_slug}/p/{page_slug}` с уникальностью slug внутри space (проще), либо материализованный `path`.

**Рекомендация MVP:** уникальность `(space_id, slug)` глобально в space; путь в UI строится из дерева, не обязательно отражать вложенность в URL.

### PageVersion (снимок версии)

При каждом значимом сохранении создаётся неизменяемая запись.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | |
| `page_id` | UUID | |
| `version` | int | 1, 2, 3… в рамках страницы |
| `title` | string | |
| `content` | JSON | Копия блоков |
| `edited_by` | user_id | |
| `created_at` | timestamp | |

**Когда создавать версию:** по debounce автосохранения (например, не чаще 1 раза в 30–60 с при активном редактировании) **и** при явном «Сохранить» / смене видимости / публикации — чтобы не раздувать хранилище.

### PublicShare (публичная публикация)

Отдельная сущность для публичного доступа без логина.

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | UUID | |
| `page_id` | UUID | Одна активная публикация на страницу в MVP |
| `token` | string | Случайный неугадываемый сегмент URL: `/pub/{token}` |
| `settings` | JSON | `noindex`, `comments_enabled`, `show_author`, `show_updated_at` |
| `enabled` | bool | |
| `created_by` | user_id | |
| `created_at` | timestamp | |

Включение `visibility = public` **и** `enabled = true` для PublicShare требует **двухшагового подтверждения** в UI (чекбокс + модальное окно).

### Упоминания и ссылки

- **Внутренняя ссылка на страницу:** в блоке хранится `type: page_link`, `page_id` или `href` с разрешением при переименовании (предпочтительно `page_id`).
- **Упоминание пользователя:** `type: mention`, `user_id`.

Индекс для поиска: полнотекст по `title` страниц и сериализованному тексту из блоков.

## Семантика видимости (зафиксировано для MVP)

| `visibility` | Авторизованные | Аноним |
|----------------|----------------|--------|
| `private` | Только участники space с ролью не ниже contributor **и** Admin; **Viewer не видит** private-страницы (черновики) | ❌ |
| `internal` | Все участники space с любой ролью | ❌ |
| `public` | Все участники space + любой держатель публичной ссылки | ✅ по `/pub/{token}` |

*Альтернатива (если нужны «приватные» страницы для Viewer):* трактовать `private` как «только редакторы», `internal` как «все в space». Текущая таблица согласована с [ROLES.md](./ROLES.md).

## Дерево страниц

- Иерархия: `parent_id` + `position`.
- Перемещение: обновление `parent_id` и `position` сiblings; проверка циклов запрещена.
- Удаление: каскадное мягкое удаление детей или запрет удаления родителя при наличии детей — выбрать в реализации; для UX чаще: мягко удалять поддерево.

## Формат контента (блоки)

Абстрактная схема (пример):

```json
{
  "version": 1,
  "blocks": [
    { "id": "blk_1", "type": "heading", "level": 1, "text": "Заголовок" },
    { "id": "blk_2", "type": "paragraph", "spans": [{ "text": "Текст ", "marks": [] }] },
    { "id": "blk_3", "type": "page_link", "page_id": "uuid", "label": "Другое" }
  ]
}
```

Детализация типов блоков — в [PRD-MVP.md](./PRD-MVP.md).

## Версионность и откат

1. Пользователь открывает историю → список версий с автором и временем.
2. Выбор двух версий → **diff** (по текстовому представлению или по JSON-diff блоков — на усмотрение реализации).
3. **Откат:** создаётся новая версия с содержимым выбранной старой + запись в аудит-логе.

## Аудит (минимум)

События: `page.published_public`, `page.visibility_changed`, `page.deleted`, `user.role_changed`, `space.created`.
