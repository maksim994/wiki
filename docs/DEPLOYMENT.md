# Требования к self-hosted развёртыванию и эксплуатации

Документ описывает, как администратор устанавливает корпоративную wiki на своём сервере (VPS / выделенный сервер). Облачный managed-вариант — вне MVP.

## Целевой сценарий

- ОС: Linux x86_64 (рекомендуется Ubuntu LTS 22.04+).
- Оркестрация: **Docker** + **Docker Compose**.
- Доступ из интернета только через **HTTPS** (reverse proxy).

## Компоненты состава

| Сервис | Назначение |
|--------|------------|
| **app** | HTTP API + отдача SPA (или SSR — по выбору стека) |
| **db** | Реляционная БД (рекомендуется **PostgreSQL** 15+) |
| **search** (опционально этап 2) | Полнотекстовый индекс (**Meilisearch** / встроенный FTS Postgres) |
| **storage** | Объектное хранилище или том для вложений: локальный volume / S3-совместимое |

Минимальный MVP: `app + postgres + volume для uploads`.

## Переменные окружения (пример категорий)

Обязательные к документированию в `.env.example`:

- `APP_URL` — публичный базовый URL (`https://wiki.company.com`)
- `DATABASE_URL` — строка подключения Postgres
- `SESSION_SECRET` / `JWT_SECRET` — криптостойкие секреты
- `FILE_STORAGE` — `local` или `s3`
- При S3: `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION`
- `SMTP_*` — для сброса пароля и приглашений (опционально в MVP, но полезно)
- `TRUST_PROXY` — при работе за reverse proxy
- `PUBLIC_SIGNUP_ENABLED=false` — по умолчанию выключено

## Сеть и безопасность

- Порты БД **не** публиковать наружу; только внутренняя Docker-сеть.
- TLS терминируется на **Nginx**, **Caddy** или **Traefik**.
- Заголовки: `X-Forwarded-Proto`, `X-Forwarded-For` — доверять только прокси.
- Резервное копирование: регулярный dump Postgres + синхронизация volume с файлами.

## Обновление версии

1. Остановить контейнеры (или rolling, если предусмотрено).
2. Подтянуть новый образ `app`.
3. Применить миграции БД (автоматически при старте или отдельной командой).
4. Запустить заново.

Документировать обратно совместимые изменения и процедуру отката (restore из бэкапа).

## Наблюдаемость (минимум)

- Healthcheck endpoint: `GET /health` (liveness).
- Структурированные логи в stdout для сбора через Docker logging driver.
- Опционально: метрики Prometheus в post-MVP.

## Ресурсы (ориентир для малой команды)

- CPU: 2 vCPU
- RAM: 2–4 GB (Postgres + app)
- Диск: SSD, 20 GB+ с учётом вложений

## «Обычный хостинг» без Docker

Если требуется установка без Docker (позже): поставлять бинарник + systemd unit + инструкция по Postgres; в MVP приоритет — **Compose**.

## Чеклист администратора после установки

- [ ] Задан `APP_URL` и HTTPS
- [ ] Создан первый пользователь Admin (bootstrap CLI или wizard)
- [ ] Отключена публичная саморегистрация
- [ ] Настроены бэкапы БД и файлов
- [ ] Проверена публичная страница: доступ только по ссылке
