# Состав MVP и границы продукта

Документ фиксирует, что входит в первую версию корпоративной self-hosted wiki и что сознательно откладывается.

## Цель MVP

Дать компании закрытую базу знаний с блочным редактором в духе Notion, поиском, версионностью, комментариями и выборочной публикацией отдельных страниц наружу по ссылке — без привязки к SaaS.

## Входит в MVP

| Область | Содержание |
|--------|------------|
| **Развёртывание** | Self-hosted; Docker Compose (`app`, БД, хранилище файлов); конфигурация через `.env`; reverse proxy и HTTPS; резервное копирование |
| **Доступ** | Локальные аккаунты (email + пароль); регистрация по умолчанию выключена; пользователи через админа или invite |
| **Роли** | `Admin`, `Editor`, `Viewer` — см. [ROLES.md](./ROLES.md) |
| **Контент** | Пространства (spaces); дерево страниц; slug-URL; перемещение страниц; блочный редактор (базовые блоки, slash-команды, автосохранение) |
| **Связи** | Внутренние ссылки на страницы; упоминания пользователей |
| **Публикация** | Статусы страницы: приватная / внутренняя / публичная; публичная страница по URL без логина; подтверждение при включении публичного режима; настройки: noindex, комментарии, метаданные автора/даты |
| **Поиск** | Полнотекстовый поиск; фильтры по space, видимости, «мои страницы» |
| **Версии** | История версий, diff, откат; аудит ключевых действий |
| **Соц.** | Комментарии под страницей; уведомления в приложении; подписка на страницу/раздел |

## Не входит в MVP (вторая очередь)

Следующие возможности **не** реализуются в первой версии, чтобы уложиться в сроки и снизить риск:

- Совместное редактирование в реальном времени (CRDT/OT)
- Базы данных и представления как в Notion
- Workflow согласования / ревью перед публикацией (кроме явного подтверждения публичного доступа)
- SSO (SAML/OIDC), LDAP/AD, OAuth (Google, Microsoft)
- Отдельные гостевые аккаунты для внешних пользователей системы
- AI: поиск ответов, суммаризация, генерация
- Права на уровне отдельных блоков внутри страницы
- Расширенная аналитика просмотров и воронок

## Критерии «MVP готов»

1. Развёртывание по документации за разумное время на типичном VPS.
2. Новый пользователь создаётся только администратором или по приглашению.
3. Редактор строит иерархию страниц и наполняет контент без обязательного знания Markdown.
4. Пользователь с ролью Viewer находит материалы через поиск и навигацию.
5. Одна страница может быть открыта публично по ссылке без раскрытия остального инстанса.
6. Изменения страниц отслеживаются по версиям с возможностью отката.
